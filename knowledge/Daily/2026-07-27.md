# 2026-07-27

## Краткий итог дня

Экран подписки показывает фактические лимиты, а основные настройки клуба теперь действительно
сохраняются и применяются в CRM: валюта, часовой пояс, рабочие часы, контакты и язык коммуникаций.
Telegram-бот использует единый профиль клуба, а сотрудник может менять язык интерфейса RU/UZ/EN.
Владелец теперь отдельно привязывает Telegram без телефона и получает защищённую ежедневную
операционную сводку своего клуба.

## Что было сделано

- Переработан экран `/settings/subscription`: текущая подписка, срок действия, стоимость и
  ключевая ёмкость клуба собраны в верхнюю сводку.
- Добавлен tenant-scoped расчёт фактического использования всех десяти entitlement-лимитов:
  клиенты, сотрудники, филиалы, товары, роли, интеграции, AI-запросы, Telegram-сообщения,
  импорты и экспорты.
- Постоянные лимиты отделены от месячных расходов; для каждого показаны использовано, лимит и
  доступный остаток.
- Карточки доступных тарифов переведены на Card/Badge/Button/Tabs из дизайн-системы и нейтральную
  двухтонную палитру. Сценарии выбора периода, заявки и отмены не изменены.
- Исправлена ложная успешная запись основных настроек: Server Action проверяет разрешение,
  обновляет строго текущий `club_id` через service-role и требует возвращённую строку от
  `.update(...).select().maybeSingle()`.
- Валюта и локаль добавлены в текущий контекст клуба; денежные значения на основных экранах CRM,
  в отчётном PDF и Telegram-отчётах форматируются из настроек клуба.
- Добавлен глобальный переключатель языка сотрудника RU/UZ/EN. Выбор хранится в `staff.settings`,
  применяется к shell, sidebar, breadcrumbs, быстрым действиям и экрану основных настроек.
- Основные данные, рабочие часы и язык клиентских сообщений входят в профиль Telegram-бота.
  Новый клиент получает название клуба, адрес, контакты, сайт и актуальные часы работы; редактор
  шаблонов поддерживает переменные `address`, `phone`, `email`, `website`, `hours`.
- Повторный `/start` для уже привязанного пользователя теперь заново показывает актуальный профиль
  клуба перед меню; `/menu` по-прежнему открывает только действия без повторной карточки.
- Исправлен тупиковый сценарий владельца в Telegram: клиентский Mini App больше не предлагает
  владельцу привязать номер. Для владельца и сотрудников используется одноразовая ссылка из
  `Интеграции → Telegram`, после которой бот открывает рабочую панель отчётов.
- Глобальная кнопка Mini App заменена на контекстное меню: личный кабинет показывается только
  привязанным клиентам, а владельцу назначаются команды панели клуба.
- Ежедневная сводка уходит только активному owner своего `club_id`, считается по часовому поясу
  клуба и защищена от повторной отправки. Добавлены сравнение выручки, средний чек, число оплат,
  посещения, новые клиенты, созданные абонементы, истечения, pending-оплаты и занятия на сегодня.
- Добавлены unit-тесты UTC-границ локального календарного дня для Ташкента и Москвы.

- Telegram webhook и редактор шаблонов сообщений.

## Исправленные ошибки

- Экран больше не прячет фактический остаток вторичных лимитов и не смешивает постоянную ёмкость
  клуба с месячным потреблением.
- Большая синяя карточка тарифа больше не выбивается из нейтральной CRM-палитры.
- Настройки клуба больше не сообщают об успехе при нулевом количестве обновлённых строк.
- Валюта больше не остаётся жёстко заданной как UZS на основных рабочих экранах после сохранения.
- Контакты и рабочие часы клуба больше не расходятся между CRM и Telegram-приветствием.
- Повторный `/start` больше не пропускает карточку клуба для уже привязанного пользователя.
- Владелец больше не попадает в цикл «привяжите номер → откройте недоступный кабинет»: роли
  Telegram получают разные точки входа, а рабочая привязка не требует номера телефона.
- Дневной отчёт больше не считает данные по UTC и не отправляется администраторам без явной
  необходимости доступа к финансовым данным.

## Найденные ошибки

- Два существующих теста security suite не проходят вне этого изменения: дубли номеров миграций и
  устаревшее source-ожидание после перехода подтверждения оплаты на RPC.

## Принятые решения

- Экран показывает реальные данные клуба, а не демонстрационные значения.
- Brand blue используется только для текущего состояния и основного действия; большие цветные
  тарифные поверхности удалены.
- Язык интерфейса хранится на сотруднике, язык клиентских сообщений — на клубе; сотрудники одного
  клуба могут работать на разных языках без изменения языка Telegram для клиентов.
- Рабочие часы и контакты остаются в `clubs.settings`, отдельная таблица и миграция не нужны.
- Mini App остаётся клиентским продуктом. Владелец работает с клубным ботом через отдельную
  staff-связь; финансовый автоотчёт по умолчанию получает только роль owner.
- Vercel cron остаётся ежедневным в 04:00 UTC, чтобы работать в текущем тарифном ограничении;
  диапазоны данных строятся отдельно для локального дня каждого клуба.

## Производительность

- Дополнительные usage-счётчики загружаются параллельно и только при наличии права на вкладку
  подписки; все service-role запросы явно ограничены текущим `club_id` или authenticated owner.
