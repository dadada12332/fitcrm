# 2026-07-28

## Краткий итог дня

Исправлена слишком тёмная граница под заголовком очереди удержания и изменение опубликовано
в production. После этого обработка истекающих абонементов перенесена в функциональный drawer
на самом экране удержания. Глобальный выбор RU/UZ/EN расширен с оболочки на всю CRM. Platform
Admin доведён от аудита до рабочего операционного контура: роли, промокоды, рассылки,
мониторинг Cron, историческая аналитика и системные настройки. Устаревшая верхняя системная
плашка удалена из оболочки CRM и из Platform Admin.

## Что было сделано

- Divider `Очередь удержания` переведён на системный токен `border-border`.
- В light theme подтверждён нейтральный цвет `rgb(228, 228, 231)` и толщина 1 px.
- Авторизованный `/retention` проверен локально при ширине 1280 px без horizontal overflow.
- Исправлен workflow проектной памяти: полный `docs:sync` теперь всегда создаёт Daily текущей
  даты, в том числе для задач без Git-изменений.
- Кнопка `Истекающие` и предупреждение на `/retention` открывают единый правый drawer вместо
  перехода на `/clients`.
- В drawer добавлены поиск, звонок, копирование номера, AI-разбор и inline-продление с выбором
  активного тарифа.
- Успешное продление обновляет очередь удержания через `revalidatePath("/retention")`.
- Сценарий учитывает право `clients.extend`; мутация остаётся в существующем защищённом
  Server Action.
- Добавлен lazy runtime-каталог всего CRM UI: статический и динамический интерфейс, dialogs,
  drawers, notifications, placeholders и accessibility labels переключаются вместе с shell.
- Генератор собирает только известные интерфейсные строки из source tree; неизвестные названия
  клубов, клиентов, сотрудников и тарифов остаются пользовательскими данными.
- Даты графика, retention drawer и системные значения ролей локализованы отдельно; Telegram
  preview исключён из app-перевода, потому что использует самостоятельный язык сообщений клуба.

  локали в уже смонтированном динамическом интерфейсе.
- В Platform Admin введена granular permission matrix для `platform_admin` и `super_admin`.
- Добавлено управление администраторами без hardcoded email-доступа; последний super-admin
  защищён от удаления на уровне Postgres.

## Исправленные ошибки

- Устранена тяжёлая чёрная граница под заголовком очереди удержания.
- Устранён лишний переход на другой экран при работе с истекающими абонементами.
- Устранена частичная смена языка, русские месяцы в нерусском интерфейсе и смешанные локали
  внутри открытых notification/drawer surfaces.
- Platform Admin больше не показывает hardcoded зелёный статус неподтверждённых сервисов.
- Финансовые итоги Platform больше не обрезаются лимитом строк PostgREST.
- Одобрение SaaS-подписки атомарно синхронизирует тариф, locked billing terms и заявку.
- Действия Platform с клубами, поддержкой и подключениями оплат теперь проверяют ошибки,
  принадлежность заявки клубу/провайдеру и конкурентную обработку.
- Командный центр больше не переполняет рабочую область крупными MRR-карточками при узком
  desktop viewport.

## Найденные ошибки

- SMS-провайдер и независимый Vercel uptime probe всё ещё не подключены; Platform показывает
  это как `Не подключено`, а не как исправный сервис.
- Историческим графикам нужен минимум второй ежедневный снимок; до этого UI показывает
  честное empty-state.

## Принятые решения

- Для внутренних divider карточек явно использовать системный `border-border`, а не только
  утилиту толщины `border-b`.
- Канонический `docs:sync` не должен зависеть от наличия Git-активности при создании Daily.
- Истекающие абонементы обрабатывать как операционную очередь внутри `/retention`: drawer
  сохраняет контекст, а продление выполняется inline.
- Не создавать новый mutating endpoint: использовать канонический `renewSubscriptionAction`
  с проверкой granular permission и RLS-safe tenant scope.
- Пользовательские данные не отправлять во внешний переводчик и не переводить в runtime:
  генерировать каталоги только из исходного UI copy, а нерусские словари грузить условно.
- Статус `настроено` в Platform не равен подтверждённому аптайму; зелёный статус допустим только
  после живой проверки.
- Кросс-клубные финансовые агрегаты считать внутри Postgres, а биллинг активировать одной
  транзакцией.
- Управление Platform разделять по явной permission matrix, а не по одному факту наличия
  административной роли.
- Получателей платформенной рассылки фиксировать при создании кампании: это сохраняет
  воспроизводимую статистику и делает повторный запуск безопасным.
- Таблицы Platform без клиентского доступа держать под RLS без permissive policies и отзывать
  права `anon`/`authenticated`; сервер работает только через service role после Platform auth.
